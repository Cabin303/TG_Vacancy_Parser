# Telegram Vacancy Parser + Splitter

Приложение для поиска вакансий в публичных Telegram-каналах: скачивает публичное превью каналов (`telegram.me/s/<канал>`), находит сообщения, соответствующие поисковым фразам (вакансии 2nd/3rd officer, OOW), сохраняет результат и нарезает его на батчи для обработки GPT.

## Возможности

- **Графический интерфейс** (tkinter):
  - монитор соединения с сетью/Telegram (парсинг блокируется при отсутствии интернета);
  - список найденных вакансий со ссылками и датами;
  - управление поисковыми фразами (добавить/изменить/выключить/удалить);
  - выбор папки сохранения результата;
  - авто-разбиение результата на батчи для GPT (включается в настройках).
- **CLI-режим** без GUI (`--parse`, `--split`, `--full`).
- **Automator-приложение macOS** (`Telegram Vacancy Parser.app`) — запуск двойным кликом без терминала.
- Отказ одного канала не роняет весь запуск; запуск можно прервать.

## Требования

- macOS (для готового `Telegram Vacancy Parser.app`).
- Python 3.11+ (проверено на 3.13). GUI использует встроенный в Python `tkinter`.

## Установка

```bash
cd TG_Vacancy_Parser

# 1. Создать виртуальное окружение
python3 -m venv .venv

# 2. Установить зависимости (файл со всеми зависимостями — requirements.txt)
.venv/bin/pip install -r requirements.txt
#   или:  source .venv/bin/activate && pip install -r requirements.txt
```

Никаких API-ключей и `.env` не нужно — приложение работает с публичными страницами каналов без авторизации.

## Подготовка данных

- **`channels.txt`** — список каналов, по одному юзернейму на строку (без `@`, как в ссылке `t.me/<канал>`):

  ```
  канал_вакансий_1
  канал_вакансий_2
  ```

- **`vacancy_filters.json`** — поисковые фразы. Файл создаётся автоматически при первом запуске из встроенного списка (парсингу нужен только оно; выключенные фразы игнорируются). Управлять удобнее из GUI.

## Запуск

**Графический интерфейс:**

```bash
./Command          # или  .venv/bin/python main.py
```

**Автоматор (двойной клик без терминала):** открыть `Telegram Vacancy Parser.app`. Внутри действие «Запустить сценарий оболочки» использует абсолютный путь к проекту — при переносе проекта поправьте его (открыть `.app` в Автоматоре → изменить команду).

**Командная строка:**

```bash
.venv/bin/python main.py --parse                    # только парсинг
.venv/bin/python main.py --split result.txt --posts 10   # разбить результат
.venv/bin/python main.py --full                     # полный цикл: парсинг → сплит
```

## Как это работает

1. Для каждого канала из `channels.txt` скачивается публичная страница `https://telegram.me/s/<канал>`.
2. Текст постов сверяется с поисковыми фразами (фразы нормализуются: нижний регистр, без пробелов).
3. Уже найденные посты пропускаются (состояние хранится в `seen_posts.json`).
4. Найденные посты записываются в `telegram_found_posts.txt` (в папке сохранения, по умолчанию — папка проекта; в GUI папку можно сменить).
5. Splitter разбивает результат на батчи по N постов (по умолчанию 10) в папку `GPT_batches/batch_001.md`, `batch_002.md`, … — эти файлы можно отдавать GPT.

## Файлы, создаваемые приложением (не в git)

| Файл | Назначение |
| --- | --- |
| `channels.txt` | список каналов для парсинга |
| `vacancy_filters.json` | поисковые фразы |
| `seen_posts.json` | состояние: уже найденные посты (дедупликация) |
| `gui_settings.json` | настройки GUI (папка сохранения, постов в батче, автосплит) |
| `telegram_found_posts.txt` | результат парсинга |
| `GPT_batches/` | батчи для GPT |
| `logs/` | журнал `app.log` |
